Mobile Robotics Term Project

Team 4 — Autonomous parking and waypoint navigation on a differential-drive robot using a polar coordinate controller and LiDAR-based collision avoidance.

Overview

This project implements two autonomous driving tasks for a wheeled mobile robot running under ROS 2. Both tasks share the same core control law: a polar coordinate feedback controller that computes linear and angular velocity commands from the robot's current odometry relative to a goal pose.

All motion commands are published to /cmd_vel and robot state is read from /odom. Waypoint goals and parking targets are passed as ROS 2 launch parameters, keeping the node logic decoupled from specific map coordinates.

Task 2

Precision Parking

Navigate to a single target pose (x, y, θ) using the polar controller. First translates to the goal position, then corrects heading to match the specified angle. Stops when both position error and heading error fall below threshold.

Task 3

Waypoint Navigation

Sequences through three configurable waypoints and returns to the origin. Each segment follows a MOVE → ROTATE state machine. A collision-avoidance variant activates on the final segment using the front-facing LiDAR sector.

Control Law

The polar coordinate controller decomposes the error between the robot and its goal into three scalar quantities and produces smooth velocity commands without requiring a global planner.

-- error decomposition --
rho = sqrt(dx^2 + dy^2) -- Euclidean distance to goal
alpha = atan2(dy, dx) - theta -- heading error toward goal
beta = -(theta + alpha) -- final heading alignment error

-- velocity commands --
v = k_rho * rho
omega = k_alpha * alpha + k_beta * beta

The beta term is only applied on intermediate waypoints so the robot aligns its heading toward the next segment. On the final return-to-origin leg, only the alpha term is used.

GainValueRole
k_rho0.2Proportional speed from distance
k_alpha1.0Correction toward goal heading
k_beta−0.3 / −0.6Final heading alignment (waypoint / parking)

Waypoint Navigation State Machine

Each waypoint transition follows a two-phase sequence to prevent the robot from overshooting while turning.

MOVE
→
ROTATE
→
MOVE (next)
→
...
→
STOP

In MOVE, the polar controller drives toward the current waypoint. Once the robot is within the position threshold (0.1 m), it switches to ROTATE and pre-aligns its heading toward the next waypoint before advancing the index. The final origin waypoint skips the ROTATE phase and issues a full stop.

When collision avoidance is enabled, the scan callback can interrupt MOVE or ROTATE at any time (on the final segment only) and insert a two-step recovery sequence:

AVOID_ROTATE
→
AVOID_FORWARD
→
MOVE (resume)

LiDAR Collision Avoidance

The avoidance module monitors the front 60-degree sector of the LiDAR scan (±30 degrees around the robot's forward axis, spanning approximately 330–360 degrees and 0–30 degrees in the scan frame).

If any valid range reading in that sector falls below the safe distance threshold, the node immediately transitions to AVOID_ROTATE, spinning left at 0.8 rad/s for 1.5 seconds, then drives straight for 5.0 seconds before resuming waypoint tracking.

Avoidance is intentionally constrained to the last waypoint segment (index 3, the return-to-origin leg) to prevent unnecessary interruptions during the main navigation path.

Safe distance threshold0.5 m
Avoidance rotate duration1.5 s
Avoidance forward duration5.0 s
Avoidance angular velocity0.8 rad/s (left)
Active segmentIndex 3 only (return to origin)

Quick Start

# 1. Clone and build
mkdir -p ~/termproject_ws/src && cd ~/termproject_ws/src
git clone https://github.com/seungjae99/robotics_4.git termproject
cd ~/termproject_ws && colcon build --symlink-install
source install/setup.bash

# 2. Run tasks
ros2 launch termproject task2.launch.py
ros2 launch termproject task3.launch.py
ros2 launch termproject task3_col_avoid.launch.py
